# TinyPython Tasks

TinyPython is a synthetic Python dataset inspired by the idea behind TinyStories: if the data distribution is narrow, clean, and high quality, even very small language models can learn useful structure.

Instead of broad repository code or competitive-programming solutions, TinyPython focuses on short natural-language programming tasks paired with complete, typed, standalone Python functions.

The goal is to provide a compact instruction-to-code corpus for training and evaluating small models on Python syntax, type signatures, meaningful identifiers, simple control flow, built-in data structures, and elementary program semantics.

The dataset contains approximately 2.2 million examples generated by two local teacher models.

## Repository Layout

The files are separated by teacher model and generation run:

```text
data/
  qwen25_coder_7b_small.jsonl
  phi4_mini_small.jsonl
  qwen25_coder_7b_big.jsonl
  phi4_mini_big.jsonl
scripts/
  generate_tinypython.py
README.md
LICENSE
````

The `small` files contain the original generation run of approximately 200,000 examples in total.

The `big` files contain the expanded generation run of approximately 2 million additional examples.

There were no major intended changes to the task distribution or record format between the two runs. The files are kept separate to preserve generation provenance and allow users to load either run independently.

All files belong to a single logical `train` split.

## Dataset Configurations

The repository exposes the following configurations:

* `default`: all files and all approximately 2.2 million examples
* `combined`: an explicit alias for the complete dataset
* `big`: only the expanded generation run
* `small`: only the original generation run
* `qwen25_coder_7b`: all examples generated by Qwen2.5-Coder-7B
* `phi4_mini`: all examples generated by Phi-4 Mini

## Dataset Format

Each JSONL row contains at least these fields:

```json
{
  "task_description": "Return the number of positive integers in values.",
  "code": "def count_positive(values: list[int]) -> int:\n    count = 0\n    for value in values:\n        if value > 0:\n            count += 1\n    return count"
}
```

The full raw records also include generation metadata:

```json
{
  "model": "teacher/model-name",
  "seed": {
    "seed_id": 0,
    "input_kind": "a list of integers",
    "operation": "count matching elements",
    "condition": "positive",
    "output_kind": "an integer",
    "edge_behavior": "handle an empty input naturally",
    "implementation_style": "use an explicit loop",
    "extra_constraint": "do not mutate the input list",
    "description_style": "use a terse direct instruction",
    "naming_style": "use descriptive domain-neutral names"
  },
  "sample_index": 0,
  "task_description": "Return the number of positive integers in values.",
  "code": "def count_positive(values: list[int]) -> int:\n    count = 0\n    for value in values:\n        if value > 0:\n            count += 1\n    return count"
}
```

## Data Fields

* `task_description`: A short English instruction describing the function to write.
* `code`: A complete Python 3 function with parameter and return type annotations.
* `model`: The local teacher model used to generate the example.
* `seed`: The structured semantic seed used to prompt the teacher model.
* `sample_index`: The sampled completion index for that semantic seed.

## Dataset Creation

The examples were generated synthetically from a controlled semantic seed space.

Each seed specifies properties such as:

* input type
* operation
* condition
* expected output
* edge behavior
* implementation style
* naming variation
* instruction phrasing

A local instruction-tuned code model converted each seed into a natural-language programming task and a standalone Python function.

The generator applied structural validation before accepting an example:

* the model output had to contain the expected `<task>` and `<code>` sections
* the code had to parse as valid Python
* the code had to contain exactly one top-level function
* all parameters had to include type annotations
* the return value had to include a type annotation
* decorators were disallowed
* classes were disallowed
* imports were disallowed
* tests were disallowed
* comments and docstrings were disallowed
* `input()` was disallowed
* `print()` was disallowed

The generation script used for the dataset is included in:

```text
scripts/generate_tinypython.py
```

## Scope

The dataset is intentionally narrow.

Typical examples include:

* counting, filtering, transforming, and searching lists
* simple string operations
* dictionary selection, aggregation, and transformation
* elementary operations over two integer lists
* short typed functions using built-in Python data structures

The dataset intentionally excludes:

* stdin/stdout programs
* classes
* third-party libraries
* repository-level context
* long algorithms
* extensive explanations
* arbitrary advanced programming tasks

## Intended Uses

This dataset is suitable for:

* training small language models on task-description-to-function generation
* continued pretraining on simple Python code
* supervised fine-tuning for instruction-to-code generation
* tokenizer experiments for Python and code domains
* controlled scaling experiments
* small-scale code-generation experiments
* data-pipeline and model-training smoke tests
* controlled evaluation of syntax learning
* controlled evaluation of elementary semantic code generation

## Limitations

This is a synthetic dataset.

Accepted examples were validated structurally, but they were not exhaustively verified through semantic execution tests. Some functions may therefore be logically incorrect, underspecified, redundant, near-duplicates, inconsistent with their task descriptions, or incorrect for uncommon edge cases.

The task distribution is deliberately constrained and should not be treated as representative of real-world Python programming.

Models trained only on this dataset may overfit to short standalone functions and may perform poorly on larger programs, multi-file projects, external libraries, classes, object-oriented code, I/O-heavy programs, repository-level tasks, complex algorithms, and long-context code generation.

Because the data was generated by teacher models, users should also consider any applicable license and usage constraints associated with those teacher models.

The `small` and `big` generation runs use substantially similar generation procedures and task distributions. They should not be interpreted as formal train, validation, or test splits.

## Loading

Load the complete dataset:

```python
from datasets import load_dataset

dataset = load_dataset("BertilBraun/TinyPython")
train = dataset["train"]

print(len(train))
print(train[0]["task_description"])
print(train[0]["code"])
```

The default configuration combines all four JSONL files into one `train` split.

The explicit `combined` configuration loads the same data:

```python
combined = load_dataset(
    "BertilBraun/TinyPython",
    "combined",
)
```

Load only the expanded generation run:

```python
big = load_dataset(
    "BertilBraun/TinyPython",
    "big",
)
```

Load only the original generation run:

```python
small = load_dataset(
    "BertilBraun/TinyPython",
    "small",
)
```

Load all examples generated by Qwen2.5-Coder-7B:

```python
qwen = load_dataset(
    "BertilBraun/TinyPython",
    "qwen25_coder_7b",
)
```

Load all examples generated by Phi-4 Mini:

```python
phi4 = load_dataset(
    "BertilBraun/TinyPython",
    "phi4_mini",
)
```

Load a configuration directly as a training split:

```python
train = load_dataset(
    "BertilBraun/TinyPython",
    "big",
    split="train",
)
```

## Streaming

To stream the complete dataset without downloading and materializing it first:

```python
from datasets import load_dataset

streamed = load_dataset(
    "BertilBraun/TinyPython",
    split="train",
    streaming=True,
)

for example in streamed:
    text = example["task_description"] + "\n\n" + example["code"]
```

Stream only the expanded run:

```python
streamed_big = load_dataset(
    "BertilBraun/TinyPython",
    "big",
    split="train",
    streaming=True,
)
```

## Example Training Formatting

For simple causal language-model training, one possible formatting function is:

```python
def format_example(example):
    return example["task_description"] + "\n\n" + example["code"]
```

A basic instruction-style representation could be:

```python
def format_instruction(example):
    return (
        "Write a Python function for the following task:\n\n"
        + example["task_description"]
        + "\n\n"
        + example["code"]
    )
```

Users may wish to add their own instruction templates, chat formatting, end-of-sequence tokens, or metadata depending on the target model and training objective.
