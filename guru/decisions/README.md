# Guru-Code: the four owner decisions

Maataa can already talk, write code and build apps with a qualified local model
(see `Maataa - Start coding.command`). A Guru-Code model of our own still needs
four decisions that code cannot make. Each one is written for the owner to fill
in. Until it is filled in, the gate stays closed, and the tooling keeps refusing.
The evidence behind each decision is in
[`../CODING_PHASE5_EXECUTION_PACKET.md`](../CODING_PHASE5_EXECUTION_PACKET.md).

Mark one box per line, then add your name and the date.

## D3 · Student base: fine-tune instead of from-scratch

The current 7B recipe trains from scratch: about 140B tokens, an estimated $15.6k
or more of GPU time, and a trainer that does not yet fit an 80 GB GPU. A
fine-tune is far cheaper. It starts from an open code model that already has a
tokenizer and long context, for example Qwen2.5-Coder-1.5B-Instruct (Apache-2.0,
32k context), and trains Guru's reviewed data and Brahmi behaviour on top of it.
It needs one admitted model intake (`../data/coding/model-intake.example.json`)
and a LoRA/SFT path, which is not written yet.
