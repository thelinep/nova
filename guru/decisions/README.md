# Guru-Code: the four owner decisions

Maataa can already talk, write code and build apps with a qualified local model
(see `Maataa - Start coding.command`). A Guru-Code model of our own still needs
four decisions that code cannot make. Each one is written for the owner to fill
in. Until it is filled in, the gate stays closed, and the tooling keeps refusing.
The evidence behind each decision is in
[`../CODING_PHASE5_EXECUTION_PACKET.md`](../CODING_PHASE5_EXECUTION_PACKET.md).

Mark one box per line, then add your name and the date.

## D1 · Runtime coding model for Maataa (needed now)

The registry contains an approved teacher entry for the exact local
Qwen2.5-Coder-7B-Instruct digest, with `output_rights: may_train`. That approval
covers the recorded teacher output rights; it does not admit TinyPython or
another dataset. This D1 decision is separate: it asks whether Maataa should
use `qwen2.5-coder:7b` as its runtime coding model. D1 remains unanswered, and
the current checkout does not establish that this exact runtime digest passed
Maataa's 18-check qualification.

Maataa's six workflow capabilities in 18/18 trials on 2026-10-12. That result
does not qualify `qwen2.5-coder:7b`: its recorded run was 15/18 with all three
multi-file trials failing. No Guru-trained checkpoint exists.
